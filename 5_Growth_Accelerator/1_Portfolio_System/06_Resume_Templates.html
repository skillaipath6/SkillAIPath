Action Verb Library

Category Strong Verbs
Building/Creating Built, Designed, Developed, Implemented, Architected, Engineered, Created
Analysis Analyzed, Identified, Investigated, Evaluated, Assessed, Examined
Optimization Optimized, Improved, Enhanced, Streamlined, Reduced, Accelerated
Leadership Led, Managed, Coordinated, Directed, Mentored, Guided
Delivery Delivered, Deployed, Launched, Shipped, Released, Executed

Bullet Point Formula

Structure: Action Verb + Task + Tool/Method + Result/Impact

Examples

Good:

  • Built real-time streaming pipeline using Auto Loader processing 500K records/day with 99.9% uptime
  • Optimized medallion architecture reducing pipeline runtime from 45 min to 5 min using partition pruning
  • Implemented CI/CD with GitHub Actions automating deployment to 3 environments (dev/uat/prod)

Avoid:

  • Worked on data pipelines
  • Learned PySpark and SQL
  • Participated in project development

Metrics to Include

  • Data Volume: 500K records, 25 Cr portfolio, 13 dimensions, 7 facts
  • Performance: 45 min → 5 min, 60% reduction, 99.9% uptime
  • Scale: 138 components, 14 serving endpoints, 3 environments
  • Quality: 98% validation pass rate, zero data loss
  • Efficiency: Automated 80% of manual workflows

Common Mistakes

  • Too long: Keep to 1 page (2 pages only if 5+ years experience)
  • Generic summary: "Hardworking team player" - Delete this
  • Responsibilities not achievements: "Responsible for pipelines" vs "Built 5 pipelines processing 500K records"
  • No metrics: Always quantify impact
  • Outdated skills: Remove MS Office unless specifically relevant
  • Typos: Run through Grammarly 3 times
  • Bad formatting: Stick to clean, ATS-friendly template

ATS (Applicant Tracking System) Tips

ATS-Friendly Formatting

  • Use standard section headings (Summary, Experience, Education)
  • Stick to simple fonts (Arial, Calibri, Times New Roman)
  • Avoid tables, columns, headers/footers
  • Use standard bullet points (not custom icons)
  • Save as PDF and .docx for different systems

Keyword Optimization

Mirror job description keywords naturally in your resume:

  • If JD says "PySpark" - use "PySpark" (not "Apache Spark Python API")
  • If JD says "CI/CD" - use "CI/CD" (not "continuous integration")
  • If JD says "Data Engineer" - use exact title in summary

Tailoring for Job Applications

Product Company Resume Focus

  • Emphasize: End-to-end ownership, automation, scalability
  • Highlight: CI/CD, DevOps, production deployment
  • Show: System design thinking, multi-environment workflows

Service Company Resume Focus

  • Emphasize: Client deliverables, business impact, stakeholder communication
  • Highlight: Analytics, dashboards, SQL proficiency
  • Show: Domain knowledge, requirement gathering

Startup Resume Focus

  • Emphasize: Speed of execution, versatility, hands-on building
  • Highlight: Full-stack data skills, quick iteration
  • Show: Scrappy problem-solving, 0-to-1 projects

Resume Checklist

Before Sending:
  • 1 page only (unless 5+ years experience)
  • Contact info at top (phone, email, LinkedIn, GitHub)
  • Summary section with Databricks/data engineering focus
  • Technical skills section with relevant tools
  • Experience bullets follow Action + Task + Tool + Result formula
  • Every bullet has a metric or quantified impact
  • Projects section with GitHub links
  • No typos (run through Grammarly 3x)
  • ATS-friendly formatting (simple, clean)
  • Tailored keywords from job description
  • Saved as PDF and .docx versions
  • File name: FirstName_LastName_DataEngineer_Resume.pdf

What Recruiters Look For (6-Second Scan)

  1. Title/Summary: Does it match the role?
  2. Recent experience: Relevant work in last 1-2 years?
  3. Technical skills: Do they have our tech stack?
  4. Metrics: Any quantified achievements?
  5. Education: Minimum qualification met?
  6. Overall impression: Professional formatting?

Optimize for the 6-second scan: Make these 6 elements pop visually.
