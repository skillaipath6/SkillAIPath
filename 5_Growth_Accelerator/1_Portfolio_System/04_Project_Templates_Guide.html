GitHub Actions Workflow (Optional)


Add `.github/workflows/databricks-deploy.yml` for CI/CD:



name: Databricks Deploy
on: [push]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Setup Databricks CLI
        run: pip install databricks-cli
      - name: Deploy Bundle
        env:
          DATABRICKS_TOKEN: ${{ secrets.DATABRICKS_TOKEN }}
          DATABRICKS_HOST: ${{ secrets.DATABRICKS_HOST }}
        run: databricks bundle deploy

STEP 3: Customize Data Schema (3-4 hours)


Dimensions (SCD Type 2)


Replace retail dimensions with your domain:


**Retail (Original)**

- dim_customer (customer_id, name, email, tier)

- dim_product (product_id, name, category, price)

- dim_store (store_id, city, region, square_feet)


**Your Domain Examples**


Fintech:

- dim_customer → dim_borrower (borrower_id, name, cibil_score, employment_type)

- dim_product → dim_loan_product (product_id, loan_type, interest_rate, tenure)

- dim_store → dim_branch (branch_id, city, region, staff_count)


Healthcare:

- dim_customer → dim_patient (patient_id, name, dob, insurance_provider)

- dim_product → dim_procedure (procedure_id, name, department, cost)

- dim_store → dim_facility (facility_id, city, bed_count, specialty)


**Action Items:**

1. Update 2_Medallion_Architecture/01_DIMENSIONS/ notebooks

2. Rename tables in Unity Catalog schema

3. Update foreign key relationships in facts


---


STEP 4: Customize Fact Tables (2-3 hours)


Facts (Star Schema)


Replace retail facts with your domain events:


**Retail (Original)**

- fact_sales (order_id, customer_key, product_key, store_key, revenue, quantity)

- fact_inventory (product_key, store_key, stock_level, reorder_point)


**Your Domain Examples**


Fintech:

- fact_sales → fact_loans (loan_id, borrower_key, product_key, branch_key, disbursed_amount, status)

- fact_inventory → fact_repayments (repayment_id, loan_key, payment_date, amount, status)


Healthcare:

- fact_sales → fact_appointments (appointment_id, patient_key, procedure_key, facility_key, date, outcome)

- fact_inventory → fact_bed_occupancy (facility_key, date, occupied_beds, available_beds)


**Action Items:**

1. Update 2_Medallion_Architecture/02_FACTS/ notebooks

2. Modify grain definition (what does one row represent?)

3. Adjust aggregation logic in gold layer

Common Pitfalls


1. **Forgot to update config.py** - Catalog and schema names still say "bharatmart"

2. **Mixed terminology** - Some places say "customer", others say "borrower"

3. **Broken foreign keys** - Renamed dimension but forgot to update fact table joins

4. **Incomplete rebranding** - Dashboard titles still say "BharatMartDBX"

5. **Stale documentation** - README describes retail but code is fintech
