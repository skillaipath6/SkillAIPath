Implementation Guide

Getting Started — Building a Genie Agent

A complete, step-by-step walkthrough of how each SkillAIPath Genie Space was created, configured, tested, validated, and shared in Databricks.

i

A note on terminology. Databricks currently refers to Genie Spaces as Genie Agents.

This documentation may use "Genie Space" because that is the terminology used in the SkillAIPath project, while the current Databricks UI/docs may display "Genie Agent." These refer to the same underlying feature — Genie Space is the former name and Genie Agent is the current name, not two different products.

Prerequisites

Before creating a Genie Agent, confirm the following are in place.

  • Databricks workspace access
  • Unity Catalog tables/views registered for the target business domain
  • Appropriate permissions on the required data
  • Access to a Pro or Serverless SQL Warehouse
  • Permission to use the selected SQL Warehouse
  • Required access to the source tables
i

Genie Agents use governed Unity Catalog data and require a Pro or Serverless SQL Warehouse.

E. Business Definitions

Revenue

definition
Revenue = SUM(fact_sales.finalprice)

finalprice is the tax-inclusive final transaction amount and is the sole approved measure of Revenue.

Orders

Each row in fact_sales represents one order because OrderID is unique per row.

validation
COUNT(DISTINCT OrderID) = 30,000

Average Order Value

definition
Average Order Value =
SUM(finalprice) / COUNT(DISTINCT OrderID)

Active Customer

A customer who made at least one purchase within the last 30 calendar days based on OrderDateID.

Quantity Sold

definition
SUM(ProductQuantity)

Order Date

OrderDateID is stored as:

format
YYYYMMDD

Example:
20260808 = August 8, 2026

Business Definitions

Low Stock

definition
StockQuantity < 10

Out of Stock

definition
StockQuantity = 0

Current Inventory

Use the latest available DateID. Do not sum inventory across all historical dates for current-stock questions.

Current Inventory Value

definition
SUM(StockValue)
-- using only the latest available DateID

Stock by Warehouse

Aggregate StockQuantity by warehouse using the latest available DateID unless another date is explicitly requested.

Reorder Level

!

There is no verified reorder-level column in the configured tables. Do not invent reorder thresholds.

Documentation Rules

Principles enforced throughout this implementation guide.

1Never invent table names.
2Never invent column names.
3Never invent RFM thresholds.
4Never invent reorder thresholds.
5Never claim a relationship that has not been confirmed.
6Clearly distinguish confirmed, configured, and requires validation information.
7Keep all SQL / table names exactly as provided.
8Use consistent naming across all 3 Genie Spaces.
9All code blocks are copyable.
10Copy buttons implemented with vanilla JavaScript.
11Sticky left navigation sidebar.
12Section IDs provided for direct navigation.
13Back to Top control available throughout.
14Search / filter functionality across documentation sections.
15Status badges: Configured, Validated, Requires Validation.
16Tables and cards used wherever they improve readability.
17No fabricated validation results.
18Customer Insights Q&A is not claimed as fully validated — the mart_rfm_analysis schema has not yet been confirmed.
